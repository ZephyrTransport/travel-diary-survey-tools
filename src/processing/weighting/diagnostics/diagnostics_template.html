{{ nums.comparison }} — {{ titles.comparison }}

One row per fitted profile. Every profile is balanced to the same controls, so the weight totals should agree.

How to read this
  • Two rows that match exactly mean both profiles selected the same records, so two weighting runs produced the same result. Check whether the settings that distinguish the profiles have any effect.
  • Σ weights should agree across profiles to within a fraction of a percent, since all profiles are weighted to the same regional totals. A profile well below the others is not reaching its targets.
  • ESS % and max/med are lower for a profile that includes more records, because the same population is spread across more of them.

How PUMAs are allocated to the target zones. Hover a zone for each profile's sample count.

How to read this
The crosswalk lets any target geography be used, whatever its relation to PUMA boundaries. Where a zone and a PUMA overlap, the PUMA is split by the block-group population share that falls in the zone; where a PUMA lies entirely inside one zone, its allocation is 100% or 0%. Boundaries are simplified to about 10 m, which is not visible at this scale and keeps the file small.

{{ nums.cascade }} — {{ titles.cascade }}

Records included and records weighted at each level, for every profile.

How to read this
  • Usable: meets the profile's criteria for that level.
  • Weighted: usable and assigned a weight.
  • Unweighted: usable but assigned no weight. Below the household level, this means the record's household was excluded, so a person can be usable and still have no weight. At the household level, it means the household is outside every control zone (see the coverage table below).

Redistribution of dropped records' weight

Dropped records' weight is redistributed among the remaining records at that level. The table shows each record's {{ term("ratio", "weight divided by the weight of the record it belongs to") }}, such as a person's weight divided by their household's; 1.0 means nothing was dropped.

How to read this
Every remaining record that belongs to the same higher-level record is scaled up by the same factor. A maximum of 10 means one person carries the weight of a ten-person household. This is arithmetically correct, but records with high ratios have a large influence on estimates, so check how many there are.

How each level's weights relate to the level above

For each set of weights, whether the weights at a level were copied from the level above, redistributed from it, or adjusted afterwards. Includes weights supplied with the survey.

How to read this
  • Copied: every record has the same weight as the record it belongs to. Comparing weight sets at this level shows nothing that the level above does not.
  • Redistributed: records that belong to the same higher-level record, such as the trips on one day, are all scaled by the same factor, so totals at this level stay consistent with the level above.
  • Adjusted per record: records that belong to the same higher-level record were scaled by different factors after the weights were assigned. Totals calculated at this level will not match the same totals calculated at the level above; for example, trip-based totals will not match day-based totals. Groups with unequal adjustments counts the higher-level records where this occurs, and Largest difference is the largest ratio between two factors within one of them.
Days are excluded, because a person's weight is divided among their days by design.

Day split identity

A person's weight is divided among their usable days, so each person's day weights must add up to the person weight.

How to read this
Any gap larger than rounding error indicates a software defect. With no usable lower-level record counts persons who have a weight but no usable day. Their weight is not passed down to the day level, rather than being moved to other persons, which would distort day-level totals.

{{ nums.imputation }} — {{ titles.imputation }} — {{ pane.profile }}

Estimated probabilities used in place of missing control values, within this weighting run only. This is not the survey imputation step and does not change survey data.

How to read this

The survey imputation step assigns a value to each missing field and saves it to the survey tables. The values described here are used only within this weighting run and are discarded afterwards. The control totals come from PUMS and are not changed.

A household with a missing control value would still count toward the total number of households, but would be left out of that control's target. Instead, the missing value is replaced with probabilities from a Random Forest model trained on complete PUMS records, for example 0.6 male and 0.4 female (fractional imputation, Kim & Fuller 2004). This keeps the household in that target; it is not a statement about the household itself.

The table shows how much of the sample relies on these estimates and how reliable the model is. Controls with more than 25% missing values are flagged. If model quality is also low, consider removing the control as a target, because its target is then met largely by estimated values. {{ term("logloss") }} below 0.5 and {{ term("f1") }} above 0.7 are good. A dash means no model was fitted, either because the control had no missing values or because a category had too few records to test.

{{ nums.balancer }} — {{ titles.balancer }} — {{ pane.profile }}

Whether weighting succeeded in each zone, how closely weighted totals match their targets, and how much the weights vary.

How to read this
  • Conv?: whether weighting reached the required accuracy within the maximum number of iterations.
  • Household / Person: total households and persons, from the first household-level and person-level control. If either does not match, consider increasing the importance of h_total or p_total. Surveys tend to under-sample large households, which lowers the person total.
  • {{ term("cv") }} depends heavily on the number and type of controls: below 0.6 is typical only with 2–3 household controls; 0.6–1.0 with a moderate specification of 4–6; 1.0–1.5 with many controls, including many person-level controls, and is not a problem if the targets are met; above 1.5, check for conflicting controls or categories with few records.
  • {{ term("ess") }} depends on the specification too: above 60% usually needs few controls or a very large sample; 40–60% is typical for a travel diary survey balancing 6–10 controls including person-level ones; 30–40% is common with many person-level controls; below 30% means a few records probably carry much of the weight, so consider combining categories, removing conflicting controls, or changing the expansion factor limits.
  • Each person-level control (age, gender, employment, commute mode, and so on) is counted per household, and each one added gives the household weights more targets to meet at once. With five or more, ESS is usually 35–55%.

{{ nums.quality }} — {{ titles.quality }} — {{ pane.profile }}

How much the weights vary, and how far weighting moved them from their starting values.

How to read this
Weights should be roughly log-normal. The charts use a log scale, so they should look roughly bell-shaped. Several peaks are not necessarily a problem, but suggest that a few variables, such as one large control category, are driving the weights. {{ term("ef", "Expansion factors") }} at the configured limits mean weighting would have moved those households further if allowed. The sample is too small for the controls, and some categories or zones should be combined.

{{ nums.sparsity }} — {{ titles.sparsity }} — {{ pane.profile }}

Unweighted sample counts per control category and zone, with the PUMS target in italic parentheses. Cells under 30 records are red.

How to read this
  • A zone with a low count overall is a candidate for merging with another. Merged zones need not be adjacent, but adjacency is easier to interpret and usually matches the wider geography.
  • A category low in every zone is a candidate for a global merge, such as 65+ in place of 65–74, 75–84 and 85+.
  • A low count in one zone and category can be merged for that zone alone, but category definitions that differ between zones are hard to track and interpret.
  • There is no fixed threshold for a low count. The warning here is at 30 records; 10 is a common minimum for reliable estimates.
  • A low count matters less when the category is also a small share of the population. If the PUMS target is low too, the category is a strong candidate for merging.
